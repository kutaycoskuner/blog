Extending a Blog with a Parallel Agile Devlog System

I originally maintained a selective essay-based blog, but over time I realized it no longer aligned with how I work or how I want to share development progress.

Originally I aimed to use more active mainstream platforms like bluesky, mastodon and linkedin. I have even created an automation tool to share same content of these various platforms. However, different format and limitations pushed me to handle and organize this problem on my own.

Rather than replacing it the blog, I now run a blog and a devlog system side by side, each serving a different purpose.


Devlog overview

Why I Extended the Format

A few issues kept coming up:

  • A traditional blog naturally pushes toward polished, self-contained essays rather than ongoing development updates.
  • I often spent too much time refining individual posts—sometimes stretching a single idea across months or even years.
  • In the process, many small but useful insights and experiments were never properly documented.

At some point, it became clear that I needed a lighter system for capturing day-to-day progress without losing context or momentum.

Introducing a Parallel Devlog

To solve this, I introduced a micro-oriented devlog that runs alongside the blog.

The idea is to document development as it happens, in small increments, instead of waiting for a fully structured post.

This makes it easier to:

  • Share progress more consistently (often daily or per task)
  • Lower the friction of writing
  • Capture small insights that would otherwise be lost
  • Avoid over-polishing or “finishing” posts before publishing

The blog stays focused on more structured, reflective writing, while the devlog captures the continuous stream of development work.

System Architecture

The setup is still based on my existing stack:

  • Markdown for content
  • Svelte for UI rendering
  • Astro for static generation and structure

On top of this, I added a metadata layer to support the devlog system.

Metadata-Driven Devlog Overview

As the number of entries grows, I needed a way to navigate them properly.

The main requirements were:

  • Filtering entries
  • Sorting by different criteria
  • Grouping by categories and tags
  • Quickly browsing past work

To handle this, each devlog entry has a corresponding JSON metadata entry.

This metadata acts as the source of truth for the overview interface.

On the Svelte side, the devlog index is built dynamically from it, with filtering and sorting handled in the UI layer.

Example Entry Structure

A typical entry looks like this:

{
  "visibility": true,
  "date": "2026-04-10",
  "title": "Pixel Scene: Color Quantization and Outlines",
  "slug": "devlog/20260410-immersion-pixel-3",
  "category": "devlog",
  "keywords": [
    "graphics",
    "webgl",
    "real-time-rendering",
    "three.js"
  ]
}

Additional extension was to navigate between posts, without retuning the overview page. For this, I added a hidden devlog navigation to my main layout.

        <DevlogNav client:idle />


Devlog post and navigation

If the link is clicked from devlog, an index variable is assigned to a post and its appearing.

In the future, I am planning to implement this data programatically through python script to avoid mistakes, as well as automate the process a bit more.
